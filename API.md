# MindSet API

Открытый API для интеграций: скриптов, выгрузок и своих приложений.
Версия в пути — `/api/v1`: ломающие изменения выпускаются только под новым префиксом.

Базовый адрес в проде: `https://alceacore.ru/mindset/api`, локально: `http://127.0.0.1:8080`.
Ниже пути указаны без префикса развёртывания.

## Авторизация

Доступ выдаётся токеном интеграции. Токен создаётся в приложении: «Настройки» → «Интеграции»,
и показывается один раз — второй раз значение не восстанавливается, можно только отозвать
токен и создать новый.

Значение передаётся в заголовке:

```
Authorization: Bearer msk_…
```

Правила:

- префикс значения — `msk_`, дальше 32 случайных байта в base64url (всего 47 символов);
- в базе лежит только SHA-256 хеш: по украденной базе токен не восстановить;
- токен действует, пока не истёк срок и пока он не отозван; отзыв мгновенный;
- cookie-сессия приложения на `/api/v1` не действует, а токен не действует на внутренние
  маршруты (`/sets`, `/boards` и остальные) — это разные способы доступа;
- использование видно владельцу в поле `last_used_at` (обновляется не чаще раза в час).

Токен даёт доступ только к своим данным: чужие сеты, коллекции и доски по нему недоступны.

```bash
curl -H "Authorization: Bearer $MINDSET_TOKEN" \
  http://127.0.0.1:8080/api/v1/me
```

## Формат ответа

Ответы повторяют формат внутреннего API приложения: объект с полем `status` и полезной
нагрузкой рядом.

```json
{
  "status": "success",
  "user": { "id": 3, "login": "verifyuser", "role": "user" }
}
```

Ошибки — тот же объект с `"status": "fail"` и человекочитаемым `message`.
В окружении `development` добавляется поле `dev` с текстом ошибки для отладки.

## Эндпоинты

### GET /api/v1/me

Профиль владельца токена: `id`, `login`, `email`, `bio`, `avatar`, `date_joined`,
`email_verified`, `two_factor_email`, `role`.

### GET /api/v1/sets

Список своих сетов. Без параметра `limit` возвращаются все сеты.

| Параметр | Описание |
|---|---|
| `search` | подстрока в названии, описании и тексте заметки (до 120 символов) |
| `visibility` | `private`, `unlisted` или `public` |
| `collection_id` | только сеты из коллекции; `0` — сеты без коллекции |
| `limit` | размер страницы, `0` — без ограничения (по умолчанию), максимум 100 |
| `offset` | сдвиг для постраничного вывода |

Кроме списка ответ отдаёт `total` (всего подходящих сетов), `query`, `limit`, `offset`
и `has_more`. Содержимое заметок в списке не передаётся — полный текст приходит
в `GET /api/v1/sets/{id}`.

```bash
curl -H "Authorization: Bearer $MINDSET_TOKEN" \
  "http://127.0.0.1:8080/api/v1/sets?search=проект&limit=20&offset=0"
```

```json
{
  "status": "success",
  "sets": [
    {
      "id": 12,
      "title": "Конспект по проекту",
      "slug": "konspekt-po-proektu",
      "visibility": "private",
      "description": "",
      "date_created": "2026-11-11",
      "last_activity": "2026-11-11"
    }
  ],
  "query": "проект",
  "limit": 20,
  "offset": 0,
  "total": 1,
  "has_more": false
}
```

### GET /api/v1/sets/{id}

Один свой сет целиком: объект `set` (как в списке плюс `content` — markdown заметки),
массив `links` (связи из викиссылок) и `backlinks` (кто ссылается на этот сет).

Чужой или удалённый сет отдаёт `404`.

### GET /api/v1/collections

Личные коллекции: `id`, `title`, `color`, `position`, число сетов `sets_count`
и снимков `saved_count`.

### GET /api/v1/graph

Граф связей: `nodes` (`id`, `title`, `links`, `backlinks`, `updated`, `own`, `slug`, `login`)
и `edges` (`from`, `to`, `one_sided`). Узлы чужих сетов приходят как внешние (`own: false`),
их идентификаторы указывают на сохранённые снимки (`snapshot_id`).

## Ограничения

- Частота: `RATE_LIMIT_API_PER_MINUTE` запросов в минуту на владельца токена (по умолчанию 120).
  При превышении приходит `429` и заголовок `Retry-After`.
- Страницы списка сетов — до 100 записей; полный список отдаётся без `limit`, но для больших
  библиотек лучше ходить страницами.
- Число токенов на пользователя — 20, срок действия — до 730 дней либо без срока.
- Тело запроса — не более 4 МБ и `Content-Type: application/json`.

## Коды ответов

| Код | Когда бывает |
|---|---|
| `200` | успешный `GET` |
| `201` | токен создан (внутренний маршрут) |
| `400` | некорректный параметр или поле |
| `401` | нет токена, токен неизвестен, отозван или истёк |
| `403` | аккаунт заблокирован |
| `404` | сет или токен не найден либо он чужой |
| `409` | превышен лимит токенов |
| `429` | слишком много запросов |
| `500` | ошибка на сервере |

## Управление токенами

Эти маршруты работают по cookie-сессии приложения: они обслуживают интерфейс настроек,
снаружи по токену недоступны.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api-tokens` | список токенов: `id`, `title`, `prefix`, `created_at`, `last_used_at`, `expires_at`, `expired` |
| `POST` | `/api-tokens` | создать токен: `title` (1–60 символов) и `expires_in_days` (`0` — без срока, до 730) |
| `DELETE` | `/api-tokens/{id}` | отозвать токен |

Ответ на создание содержит `token` (запись для списка) и `value` — значение, которое
показывается один раз.

```json
{
  "status": "success",
  "message": "Токен создан. Скопируйте значение: больше оно не показывается.",
  "token": {
    "id": 4,
    "title": "Скрипт выгрузки",
    "prefix": "msk_UkdBI2",
    "created_at": "2026-11-11T15:15:24Z",
    "last_used_at": "",
    "expires_at": "2026-12-11T15:15:24Z",
    "expired": false
  },
  "value": "msk_UkdBI2…"
}
```

## Возможности интеграций

### Токены для скриптов и своих приложений

Токены создаются в приложении: настройки → вкладка «Интеграции». Работает это так:

1. нажимаете «Создать токен», даёте имя и выбираете срок (30 / 90 / 365 дней или без срока);
2. значение вида `msk_…` показывается один раз — его нужно скопировать сразу;
3. токен подставляется в заголовок `Authorization: Bearer msk_…` при обращении к `/api/v1`.

В базе хранится только SHA-256 от значения, поэтому восстановить потерянный токен нельзя — его
остаётся отозвать и создать новый. Время последнего использования видно в списке токенов
(обновляется не чаще раза в час). По токену доступно только чтение: профиль, сеты, коллекции
и граф связей; изменить данные через него нельзя.

### Темы-плагины (шаг 3 плагинов)

Тема — это данные, а не код: манифест (ключ, название, режим, базовая тема) плюс переопределения
цветовых переменных. Никакого CSS, HTML или JS не исполняется — сервер принимает только цвета
из фиксированного белого списка переменных.

```json
{
  "key": "northern-dusk",
  "title": "Северные сумерки",
  "description": "Холодный вечерний вариант",
  "mode": "dark",
  "base": "dark",
  "variables": {
    "--bg-canvas": "#0f1420",
    "--accent": "rgba(124, 199, 255, 0.9)"
  }
}
```

Правила формата:

| Поле | Правило |
|---|---|
| `key` | латиница, цифры и дефис, 3–32 символа; уникален во всей базе |
| `title` | 3–60 символов |
| `description` | до 200 символов |
| `mode` | `light` или `dark` — нужен для `color-scheme` и тёмных/светлых системных элементов |
| `base` | имя встроенной темы: `dark`, `light`, `sepia`, `nord`, `contrast`; из неё берутся все непереопределённые переменные (включая тени и фон-градиент) |
| `variables` | хотя бы одна переменная из белого списка; значение — `#rgb`, `#rrggbb`, `#rrggbbaa` или `rgba(r, g, b, a)`. Имена, которых нет в списке, и любые другие значения отклоняются с `400` |

Белый список — цвета интерфейса: фон и поверхности, рамки, текст, акцент, статусы, шапка и затемнение,
подсветка кода, граф связей, метки коллекций. Список приходит в ответе `GET /theme-packages`
(поле `variables`), чтобы интерфейс не расходился с сервером.

### Жизненный цикл темы

```
черновик (draft) ──отправить──▶ на модерации (pending) ──одобрить──▶ опубликована (approved)
        ▲                                     │                            │
        └────────── правка ◀───────── отклонена (rejected) ◀─── отклонить ──┘
```

- Черновик и отклонённую тему автор правит и удаляет; после отказа причина видна автору.
- Опубликованная тема видна всем и попадает в каталог `/themes`; править её нельзя —
  можно удалить (тогда она исчезает из каталога) или создать новую.
- Модерация — в админке на вкладке «Темы»: причина обязательна при отклонении,
  решения попадают в журнал действий админов.

### Эндпоинты тем

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| `GET` | `/themes` | все | каталог опубликованных тем (без авторизации) |
| `GET` | `/theme-packages` | автор | свои темы, лимит, белый список переменных и базовые темы |
| `POST` | `/theme-packages` | автор | создать черновик |
| `PUT` | `/theme-packages/{id}` | автор | правка черновика или отклонённой темы |
| `DELETE` | `/theme-packages/{id}` | автор | удалить тему (в том числе опубликованную) |
| `POST` | `/theme-packages/{id}/submit` | автор | отправить на модерацию |
| `GET` | `/admin/themes?status=pending` | админ | очередь модерации (`draft`, `pending`, `approved`, `rejected`, пусто — все) |
| `PUT` | `/admin/themes/{id}/status` | админ | `{"status": "approved"}` или `{"status": "rejected", "note": "…"}` |

Каталог публичный и кэшируется браузером на стороне приложения: тема применяется как набор
CSS-переменных на `<html>`, а выбранный ключ и переменные хранятся в `localStorage`
(`mindset:theme`, `mindset:theme:cache`) — поэтому тема не мигает при перезагрузке страницы.
Внутри приложения пользовательская тема называется `custom:<key>`.

### Ограничения тем

- До 10 тем на автора, по одному пакету на ключ во всей базе.
- Отправка на модерацию доступна только для черновика и отклонённой темы (иначе `409`).
- Отклонить тему без причины нельзя — иначе автор не поймёт, что исправить.



## Версионирование

- Текущая версия — `v1` (префикс `/api/v1`).
- В пределах версии добавляем поля и новые маршруты; удаление и переименование полей —
  только в новой версии.
- О новых версиях сообщаем в `CHANGELOG.md`; старая версия живёт минимум один релиз.

## Что дальше

Записи по токену пока нет: интеграции читают сеты, коллекции и граф. Создание и правка
заметок по API — следующий шаг, он появится вместе с разграничением прав токена.
