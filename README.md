# MindSet

Заметки-«сеты»: заметки со связями между мыслями, граф знаний, публикация сетов и лента сообщества.
Текущая версия — 1.5.3.

## Возможности

- **Сеты заметок**: создание, редактирование, удаление, связи между мыслями.
- **Редактор заметок**: markdown с таблицами и блоками кода, вставка разметки из буфера, импорт и экспорт
  файлов `.md` (стили и языки сохраняются, неподдерживаемые конструкции упрощаются); импорт
  спрашивает подтверждение, если в заметке уже есть текст; панель инструментов остаётся на виду
  при прокрутке длинной заметки.
- **Ссылки внутри заметки**: `[[Название сета]]` — переход к другому сету, `[[Сет|свой текст]]` — ссылка
  с подписью, `[текст](#заголовок)` — переход к заголовку внутри статьи.
- **Типографика**: два дефиса (`--`) в тексте показываются как длинное тире «—»; в блоках кода
  и в адресах ссылок замена не применяется.
- **Чтение**: место чтения запоминается для каждого сета — заметка открывается там, где вы
  остановились, в том числе после перезагрузки страницы, а возврат «назад» приводит на прежнее место.
  Заголовки, к которым ведут ссылки внутри статьи, не прячутся под шапкой.
- **Граф связей**: визуальная карта заметок сета с панорамированием и зумом, в том числе на телефоне.
- **Снимки**: сохранение и восстановление состояния сета.
- **Публикация и каталог**: публичные сеты, поиск, сортировка, копирование чужого сета себе;
  карточка сета открывается кликом в любом месте; на своих сетах видно число полученных лайков.
- **Новости проекта**: в ленте видны все закреплённые новости и одна последняя — блок ограничен
  по высоте и прокручивается, если новостей много; полный список — на странице `/news`.
- **Уведомления**: колокольчик в шапке со счётчиком непрочитанных — новые подписчики, лайки и
  комментарии к вашим сетам, регистрации по вашим приглашениям, решения модерации. Категории
  отключаются в `/settings?tab=notifications`, лайки и комментарии собираются в одну запись со счётчиком.
- **Аккаунт**: регистрация с подтверждением почты, восстановление пароля, вход по коду из письма, приглашения.
- **Админ-панель** на `/admin`: пользователи, сеты, новости, жалобы, журнал действий.
- **Изображения**: вставка в заметки и новости с загрузкой в объектное хранилище (S3).
- **Поиск**: серверный — по названию, описанию и тексту заметки (PostgreSQL + `pg_trgm`).
  Список своих сетов приходит страницами с кнопкой «Показать ещё», фильтр по доступу считает сервер.
- **Выгрузка и печать**: свои данные скачиваются одним zip (по файлу `.md` на заметку плюс `sets.json`
  с метаданными) — вкладка «Данные» в настройках; статья печатается светлой версией без интерфейса,
  из неё сохраняется PDF.
- **Офлайн**: приложение ставится как PWA (манифест и service worker), прочитанные сеты открываются
  без сети; кэш данных чистится при выходе из аккаунта.
- **Мобильная версия**: статья, редактор и граф адаптированы под узкие экраны.

## Стек

| Часть | Технологии |
|---|---|
| `back/` | Go 1.24, Fiber v2, PostgreSQL 16, JWT, AWS SDK v2 (S3), validator |
| `front/` | React 18 (Create React App), MUI 7, SCSS, react-router 6, axios, react-markdown, MDXEditor |
| Прод | Docker Compose: PostgreSQL, backend, nginx со статикой, Caddy с автоматическим HTTPS |

## Структура

```
back/                     API на Go: src/ — код, Dockerfile, README с описанием API и переменных окружения
front/                    SPA на React: src/app — код, Dockerfile
docker-compose.yml        прод-сборка: db + backend + frontend + caddy
Caddyfile                 конфигурация Caddy (HTTPS, раздача под /mindset)
CHANGELOG.md              история версий (Keep a Changelog + SemVer)
.env.production.example   шаблон окружения для docker compose
docker-compose.images.yml запуск из готовых образов GHCR
.github/workflows/        CI: тесты, проверка схемы на чистой базе, сборка и публикация образов
```

## Локальный запуск

Нужны Go 1.24+, Node 20+ и PostgreSQL 16.

Бэкенд:

```bash
cd back/src
cp .env.example .env
go run .
```

Сервер поднимается на порту из `PORT` (по умолчанию `8080`), версия видна в `GET /health`.
Письма при пустом SMTP не отправляются, а печатаются в лог, поэтому в dev ссылку подтверждения
и ссылку сброса пароля видно прямо в консоли.

Фронтенд:

```bash
cd front
npm install
npm start
```

Стартует на `http://localhost:3000`, запросы к `/api` уходят на `127.0.0.1:8080`.

## Схема БД

`back/src/db/schema.sql` применяется идемпотентно:

```bash
cd back/src
go run ./cmd/migrate
```

## Тесты

```bash
cd back/src && go test ./...
cd front && CI=true npm test
```

Браузерные проверки (Playwright) идут по живому стенду: бэкенд на `:8080`, dev-сервер на `:3000`
и тестовый пользователь из `front/e2e/seed.sql`.

```bash
# один раз: применить сид и поставить браузер
psql -h 127.0.0.1 -U postgres -d mindset -f front/e2e/seed.sql
cd front && npx playwright install chromium

# прогон
cd front && npm run test:e2e          # нужен поднятый стенд (npm start + go run .)
```

Что проверяется: на мобильных разрешениях (320/360/390/414px) ни одна страница не вылезает за
экран, шапка остаётся кликабельной; подчёркивание и маркеры списка доживают до статьи и до
сохранения; выпадающий список редактора не срывает липкую панель; серверный поиск, догрузка
страниц, выгрузка архива и печатный вид статьи. Адрес стенда переопределяется
через `E2E_BASE_URL`, логин и пароль — через `E2E_LOGIN` и `E2E_PASSWORD`.

## Прод

```bash
cp .env.production.example .env
docker compose up -d --build
```

В `.env` заполняются `DATABASE_*`, `JWT_*`, `S3_*`, `SMTP_*`, `TELEGRAM_*`, `DOMAIN`, `ADMIN_TOKEN`.
Приложение разворачивается под подпутём `/mindset`, API — `/mindset/api`, медиа — `/media`.
В проде значения-заглушки секретов не принимаются: с `change-me*` и примерными паролями приложение не стартует.

Утилиты в `back/src/cmd`: `migrate` (схема БД), `admin` (роли, блокировки), `mailcheck` (проверка SMTP).

Образы для прода собираются в GitHub Actions: по тегу `v*` они публикуются в GHCR
(`ghcr.io/alceaa/mindset-backend:<тег>`, `ghcr.io/alceaa/mindset-frontend:<тег>`). Чтобы обновляться
готовыми образами, укажите `MINDSET_TAG` в `.env` и запускайте compose с `docker-compose.images.yml`.

## Ветки и релизы

- `main` — то, что в проде: в любой момент можно задеплоить. Сюда попадают релизы и мелкие правки.
- `next` — следующая версия: мажорная разработка идёт здесь, чтобы срочные правки не тащили её за собой.
- `fix/<тема>` и `feat/<тема>` — короткие ветки под задачи: `fix/*` от `main`, `feat/*` от `next`,
  дальше pull request и merge.

Релиз — это тег. В релизном коммите обновляются `utils.Version` (бэкенд), `front/package.json`
и раздел в `CHANGELOG.md`, затем ставится тег `vX.Y.Z` — по нему CI собирает и публикует образы
в GHCR. После релиза `main` мержится в `next`, чтобы ветки не расходились.

## Версии

Номер версии задаётся константой `utils.Version` в бэкенде, виден в `GET /health` и в логе при старте.
История изменений — [CHANGELOG.md](CHANGELOG.md). Теги `vX.Y.Z` отмечают релизы: из тега на GitHub
можно оформить Release, вставив текст соответствующего раздела из CHANGELOG.
