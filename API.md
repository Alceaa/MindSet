# MindSet API

Открытый API для интеграций: скриптов, выгрузок и своих приложений.
Версия в пути — `/v1`: ломающие изменения выпускаются только под новым префиксом.

Базовый адрес в проде: `https://alceacore.ru/mindset/api`, локально: `http://127.0.0.1:8080`.
Пути ниже указаны без базового адреса: например, `GET /v1/me` в проде — это
`https://alceacore.ru/mindset/api/v1/me` (прокси отрезает `/mindset/api`, поэтому в бэкенд
приходит `/v1/me`).

## Авторизация

Доступ выдаётся токеном интеграции. Токен создаётся в приложении: «Настройки» → «Интеграции»,
и показывается один раз — второй раз значение не восстанавливается, можно только отозвать
токен и создать новый.

Значение передаётся в заголовке:

```
Authorization: Bearer msk_…
```

Правила:

- префикс значения — `msk_`, дальше 32 случайных байта в base64url (всего 47 символов);
- в базе лежит только SHA-256 хеш: по украденной базе токен не восстановить;
- токен действует, пока не истёк срок и пока он не отозван; отзыв мгновенный;
- cookie-сессия приложения на `/v1` не действует, а токен не действует на внутренние
  маршруты (`/sets`, `/boards` и остальные) — это разные способы доступа;
- использование видно владельцу в поле `last_used_at` (обновляется не чаще раза в час).

Токен даёт доступ только к своим данным: чужие сеты, коллекции и доски по нему недоступны.

```bash
curl -H "Authorization: Bearer $MINDSET_TOKEN" \
  http://127.0.0.1:8080/v1/me
```

## Формат ответа

Ответы повторяют формат внутреннего API приложения: объект с полем `status` и полезной
нагрузкой рядом.

```json
{
  "status": "success",
  "user": { "id": 3, "login": "verifyuser", "role": "user" }
}
```

Ошибки — тот же объект с `"status": "fail"` и человекочитаемым `message`.
В окружении `development` добавляется поле `dev` с текстом ошибки для отладки.

## Эндпоинты

### GET /v1/me

Профиль владельца токена: `id`, `login`, `email`, `bio`, `avatar`, `date_joined`,
`email_verified`, `two_factor_email`, `role`.

### GET /v1/sets

Список своих сетов. Без параметра `limit` возвращаются все сеты.

| Параметр | Описание |
|---|---|
| `search` | подстрока в названии, описании и тексте заметки (до 120 символов) |
| `visibility` | `private`, `unlisted` или `public` |
| `collection_id` | только сеты из коллекции; `0` — сеты без коллекции |
| `limit` | размер страницы, `0` — без ограничения (по умолчанию), максимум 100 |
| `offset` | сдвиг для постраничного вывода |

Кроме списка ответ отдаёт `total` (всего подходящих сетов), `query`, `limit`, `offset`
и `has_more`. Полного текста заметки в списке нет — приходит только короткая выдержка
`preview` (когда заметка не пустая), а целиком текст отдаёт `GET /v1/sets/{id}`.

```bash
curl -H "Authorization: Bearer $MINDSET_TOKEN" \
  "http://127.0.0.1:8080/v1/sets?search=проект&limit=20&offset=0"
```

```json
{
  "status": "success",
  "sets": [
    {
      "id": 12,
      "user_id": 3,
      "title": "Конспект по проекту",
      "slug": "konspekt-po-proektu",
      "visibility": "private",
      "forbid_copies": false,
      "description": "",
      "date_created": "2026-11-11",
      "last_activity": "2026-11-11",
      "preview": "Краткое начало заметки…",
      "likes_count": 0,
      "comments_count": 0,
      "is_liked": false
    }
  ],
  "query": "проект",
  "limit": 20,
  "offset": 0,
  "total": 1,
  "has_more": false
}
```

### GET /v1/sets/{id}

Один свой сет целиком: объект `set` (как в списке плюс `content` — markdown заметки),
массив `links` (связи из викиссылок) и `backlinks` (кто ссылается на этот сет).

Чужой или удалённый сет отдаёт `404`.

### GET /v1/collections

Личные коллекции: `id`, `title`, `color`, `position`, число сетов `sets_count`
и снимков `saved_count`.

### GET /v1/graph

Граф связей: `nodes` (`id`, `title`, `links`, `backlinks`, `updated`, `own`, `slug`, `login`)
и `edges` (`from`, `to`, `one_sided`). Узлы чужих сетов приходят как внешние (`own: false`),
их идентификаторы указывают на сохранённые снимки (`snapshot_id`).

## Ограничения

- Частота: `RATE_LIMIT_API_PER_MINUTE` запросов в минуту на владельца токена (по умолчанию 120).
  При превышении приходит `429` и заголовок `Retry-After`.
- Страницы списка сетов — до 100 записей; полный список отдаётся без `limit`, но для больших
  библиотек лучше ходить страницами.
- Число токенов на пользователя — 20, срок действия — до 730 дней либо без срока.
- Тело запроса — не более 4 МБ и `Content-Type: application/json`.

## Коды ответов

| Код | Когда бывает |
|---|---|
| `200` | успешный `GET` |
| `201` | токен создан (внутренний маршрут) |
| `400` | некорректный параметр или поле |
| `401` | нет токена, токен неизвестен, отозван или истёк |
| `403` | аккаунт заблокирован |
| `404` | сет или токен не найден либо он чужой |
| `409` | превышен лимит токенов |
| `429` | слишком много запросов |
| `500` | ошибка на сервере |

## Управление токенами

Эти маршруты работают по cookie-сессии приложения: они обслуживают интерфейс настроек,
снаружи по токену недоступны.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api-tokens` | список токенов: `id`, `title`, `prefix`, `created_at`, `last_used_at`, `expires_at`, `expired` |
| `POST` | `/api-tokens` | создать токен: `title` (1–60 символов) и `expires_in_days` (`0` — без срока, до 730) |
| `DELETE` | `/api-tokens/{id}` | отозвать токен |

Ответ на создание содержит `token` (запись для списка) и `value` — значение, которое
показывается один раз.

```json
{
  "status": "success",
  "message": "Токен создан. Скопируйте значение: больше оно не показывается.",
  "token": {
    "id": 4,
    "title": "Скрипт выгрузки",
    "prefix": "msk_UkdBI2",
    "created_at": "2026-11-11T15:15:24Z",
    "last_used_at": "",
    "expires_at": "2026-12-11T15:15:24Z",
    "expired": false
  },
  "value": "msk_UkdBI2…"
}
```

## Возможности интеграций

### Токены для скриптов и своих приложений

Токены создаются в приложении: настройки → вкладка «Интеграции». Работает это так:

1. нажимаете «Создать токен», даёте имя и выбираете срок (30 / 90 / 365 дней или без срока);
2. значение вида `msk_…` показывается один раз — его нужно скопировать сразу;
3. токен подставляется в заголовок `Authorization: Bearer msk_…` при обращении к `/v1`.

В базе хранится только SHA-256 от значения, поэтому восстановить потерянный токен нельзя — его
остаётся отозвать и создать новый. Время последнего использования видно в списке токенов
(обновляется не чаще раза в час). По токену доступно только чтение: профиль, сеты, коллекции
и граф связей; изменить данные через него нельзя.

### Библиотека тем

Тема — это данные, а не код: название, режим, базовая тема и **восемь ролей** (фон страницы,
карточки, текст, границы, главный цвет, опасное действие, предупреждение, подтверждение).
Из ролей выводятся все остальные переменные оформления, поэтому тему просто собрать и почти
невозможно сделать нечитаемой. Никакой CSS, HTML или JS не исполняется: сервер принимает
только роли и только цвета вида `#rrggbb`.

Каталога тем и модерации нет: публичного списка тем в API не существует, ключ темы уникален
только у своего автора. Темы хранятся в аккаунте (до десяти) и доступны с любого устройства,
а обмен идёт файлом или текстом — формат ниже.

```json
{
  "id": 12,
  "key": "morskaya-noch",
  "title": "Морская ночь",
  "description": "Тёмная, синяя",
  "mode": "dark",
  "base": "nord",
  "roles": {
    "canvas": "#0a1a24",
    "surface": "#10293a",
    "text": "#dff0f5",
    "border": "#1c4356",
    "accent": "#5fc4d8",
    "danger": "#e8888d",
    "warning": "#e0c07a",
    "success": "#7fd0b6"
  },
  "created_at": "2026-11-14T18:00:00Z",
  "updated_at": "2026-11-14T18:00:00Z"
}
```

Правила формата:

| Поле | Правило |
|---|---|
| `id`, `key` | только чтение: ключ собирается из названия (транслит в латиницу, 3–32 символа). Если у автора такой ключ занят, сервер возьмёт следующий свободный (`morskaya-noch-2`) |
| `title` | 3–60 символов |
| `description` | до 200 символов, необязательно; пустое — в списке под названием ничего не показывается |
| `mode` | `light` или `dark` — нужен для `color-scheme` и тёмных/светлых системных элементов |
| `base` | имя встроенной темы: `dark`, `light`, `sepia`, `nord`, `contrast`; из неё берутся тени, подсветка кода и цвета графа |
| `roles` | восемь ролей, значения — `#rrggbb`. Неизвестная роль или другой формат цвета отклоняются с `400`; недостающие роли интерфейс добирает значениями по умолчанию |

Список базовых тем и имена ролей приходят в ответе `GET /themes`, чтобы интерфейс не расходился
с сервером.

### Обмен темами: файл или текст

Внутри приложения тема выгружается и загружается одним форматом — файлом `.theme.json` или той
же строкой из буфера обмена. Импорт **ничего не применяет**: тема открывается в конструкторе,
и только кнопкой «Сохранить» попадает в библиотеку (и считается в лимит десяти).

```json
{
  "kind": "mindset.theme",
  "version": 1,
  "title": "Морская ночь",
  "description": "Тёмная, синяя",
  "mode": "dark",
  "base": "nord",
  "roles": { "canvas": "#0a1a24", "accent": "#5fc4d8", "…": "…" }
}
```

Правила разбора: обязателен `roles` (роли — из того же списка восьми), `kind` должен совпадать
с `mindset.theme`, если он указан, `version` не может быть выше текущей, а объект без ролей или
с цветом не в виде `#rrggbb` отклоняется с понятным сообщением. Имя файла собирается из названия,
а если в названии нет латиницы — из ключа темы.


### Эндпоинты тем

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| `GET` | `/themes` | автор | библиотека своих тем: список, лимит, базовые темы и имена ролей |
| `POST` | `/themes` | автор | сохранить тему (до десяти на аккаунт) |
| `PUT` | `/themes/{id}` | автор | правка своей темы: название, описание, режим, база, роли |
| `DELETE` | `/themes/{id}` | автор | удалить свою тему |

Маршруты без `/v1` — внутренние: они работают по cookie-сессии приложения (`POST /auth/login`),
и токен интеграции туда не подходит — тему создаёт и правит владелец из интерфейса.

Тема применяется как набор CSS-переменных на `<html>`, а выбранный ключ и переменные хранятся
в `localStorage` (`mindset:theme`, `mindset:theme:cache`) — поэтому тема не мигает при перезагрузке
страницы. Сама библиотека при этом лежит на сервере: на другом устройстве свои темы уже ждут
в списке. Внутри приложения своя тема называется `custom:<key>`.

### Ограничения тем

- До 10 тем на аккаунт: одиннадцатая не сохранится (`409`), пока не удалить ненужную.
- Ключ уникален в пределах автора, поэтому у двух человек темы с одинаковым названием живут
  спокойно и не получают приставок.
- В теме нет ничего, кроме восьми цветов, базовой темы и режима: ни CSS, ни HTML, ни картинок.



## Версионирование

- Текущая версия — `v1` (в проде `https://alceacore.ru/mindset/api/v1/…`).
- В пределах версии добавляем поля и новые маршруты; удаление и переименование полей —
  только в новой версии.
- О новых версиях сообщаем в `CHANGELOG.md`; старая версия живёт минимум один релиз.

## Что дальше

Записи по токену пока нет: интеграции читают сеты, коллекции и граф. Создание и правка
заметок по API — следующий шаг, он появится вместе с разграничением прав токена.
